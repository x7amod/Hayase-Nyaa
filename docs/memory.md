## What This Is

A single Hayase extension that searches Nyaa.si for anime torrents. Hayase is a bring-your-own-content torrent/NZB streaming client. This extension plugs into Hayase's extension system to provide torrent search results.

## Architecture

```
hayase/nyaasi.js      ← The extension. Single file, no dependencies.
hayase/index.json     ← Generated Hayase manifest (auto-generated by generate_indexes.js)
index.json            ← Same manifest at root level for direct URL access
generate_indexes.js   ← Build script that generates both index.json files
test/                 ← Test suite using Node.js built-in test runner
```

## How the Extension Works

The extension exports a `NyaaSi` class with three public methods:
- `single(query)` — search for a specific episode
- `batch(query)` — search for batch/season releases
- `movie(query)` — search for movies

Each method calls `search()` which:
1. Builds a search plan (`buildSearchPlan`) — generates multiple Nyaa RSS query terms
2. Fetches RSS from Nyaa for each query term
3. Deduplicates results by hash
4. Filters results (`matchesQuery`) — applies resolution, season, and episode filters
5. Ranks results (`rankResults`) — scores by title similarity, episode match, seeders

### Key Internal Functions

| Function | Purpose |
|----------|---------|
| `buildSearchPlan` | Generates Nyaa RSS query terms from titles. Handles single/batch/movie modes. |
| `buildSearchVariants` | Strips punctuation, brackets, colons, `!`/`?` from titles for broader matching. |
| `classifyEpisode` | Returns `'exact'`, `'range'`, `'conflict'`, or `'absent'` for a result title + episode number. |
| `detectSeason` | Extracts season number from title (S04, Season 4, 4th Season, IV, trailing bare number). |
| `detectResultSeason` | Like detectSeason but also handles "Show 4 - 10" pattern (season before episode). |
| `detectQuerySeason` | Returns max season across all query titles. |
| `stripEpisodeNoise` | Removes resolution, year, hash, season markers from title before episode classification. |
| `matchesQuery` | Main filter: exclusions → resolution → season → episode. |
| `matchesBatch` | Checks if a title looks like a batch release (keywords: batch, complete, range patterns). |
| `isPlausibleEpisode` | Returns true only if `classifyEpisode` returns `'exact'`. |
| `parseRssResults` | Parses Nyaa RSS XML into structured items. |
| `dedupeResults` | Deduplicates by hash/link/title. |

### Search Plan Generation

For **single mode** (searching for ep 10 of Iruma-kun S4):
1. Base titles: `Mairimashita! Iruma-kun 4`
2. Stripped variants: `Mairimashita Iruma-kun 4` (no `!`)
3. Episode-qualified: `Mairimashita! Iruma-kun 4 10`, `Mairimashita Iruma-kun 4 10`
4. Season-qualified: `Mairimashita Iruma-kun 4 S04 10`, `Mairimashita Iruma-kun 4 Season 4 10`, `Mairimashita Iruma-kun 4th Season 10`

For **batch mode** (searching for Iruma-kun S3 batches):
1. Base titles: `Mairimashita! Iruma-kun 3`
2. Stripped variants: `Mairimashita Iruma-kun 3`
3. Batch-qualified: `... batch`, `... complete`, `... 1-21`, `... 01-21`, `... 01 ~ 21`

### Nyaa RSS Behavior

- Nyaa uses AND semantics for search queries — `Mairimashita Iruma-kun 4 10` returns results containing ALL of those words
- RSS returns max 75 items per query, sorted by date (newest first)
- `~` is treated as a word separator by Nyaa, so `1~21` doesn't work as a range search
- `-` works as a range separator in titles but not in search queries (Nyaa treats it as AND)
- The `!` in titles like `Mairimashita!` must be stripped because scene groups like Erai-raws omit it

### Erai-raws Compatibility

Erai-raws is a major scene group that:
- Omits `!` from titles (`Mairimashita Iruma-kun` not `Mairimashita! Iruma-kun`)
- Uses `4th Season` notation instead of `S04` or `Season 4`
- Uses `01 ~ 21` (with spaces) for batch ranges

The extension handles this by:
- Stripping `!`/`?` in `buildSearchVariants` and `buildSearchPlan`
- Generating `4th Season` ordinal variants in step (4) of search plan
- Including `01 ~ 21` tilde range in batch search plan

### Season Detection

`detectSeason` tries these patterns in order:
1. `S04`, `Season 04`, `s4` — explicit S/Season notation
2. `4th Season`, `3rd Season` — ordinal + Season
3. `4th`, `3rd` — trailing ordinal (no "Season")
4. `IV`, `III` — roman numerals (trailing)
5. `4`, `3` — trailing bare number preceded by space

The trailing bare number pattern can incorrectly treat episode numbers as season numbers (e.g., `[SubsPlease] Show - 12` → season 12). This is mitigated by `detectResultSeason` which additionally checks for "Show <n> - <ep>" pattern.

### Episode Classification

`classifyEpisode` collects all numbers from a cleaned title and checks:
- `exact` — the only number found IS the requested episode
- `range` — the episode falls strictly inside a range (e.g., 5 is inside 01-10)
- `conflict` — a different number was found
- `absent` — no numbers found at all

In single mode, only `'exact'` results pass the filter. In batch mode, episode classification is skipped.

## Test Suite

Uses Node.js built-in `node:test` module. Zero dependencies.

```
test/
  helpers/
    loader.mjs    — Loads nyaasi.js and exposes internal functions
    rss.mjs       — Builds synthetic RSS XML for offline testing
    reporter.mjs  — Custom test reporter with colored output
  fixtures/
    titles.mjs    — Reusable title fixture data
  unit/           — Offline tests (runs in CI)
    classifyEpisode.test.mjs
    detectSeason.test.mjs
    matchesBatch.test.mjs
    buildSearchPlan.test.mjs
    matchesQuery.test.mjs
  integration/    — Live Nyaa tests (skipped in CI)
    nyaa-single.test.mjs
    nyaa-batch.test.mjs
    nyaa-scenegroups.test.mjs
```

Commands:
- `npm test` — run unit tests
- `npm run test:integration` — run live tests
- `npm run test:all` — run everything
- `npm run generate` — regenerate index.json manifests

To add a new test: create `test/unit/myFeature.test.mjs`. It's auto-discovered.

## Hayase Extension Format

Each extension is a JS file that `export default`s an object with:
- `single(query)` — returns `Promise<TorrentSource[]>`
- `batch(query)` — returns `Promise<TorrentSource[]>`
- `movie(query)` — returns `Promise<TorrentSource[]>`

Query object fields:
- `titles: string[]` — title variants (romaji, English, Thai, Japanese, etc.)
- `episode: number` — episode number (single mode)
- `episodeCount: number` — total episodes (batch mode)
- `resolution: string` — requested resolution (e.g., "1080")
- `exclusions: string[]` — keywords to exclude
- `anilistId: number` — Anilist ID
- `fetch: Function` — custom fetch function (for testing)

TorrentSource result fields:
- `title`, `link`, `hash`, `seeders`, `leechers`, `downloads`, `size`, `date`, `tags`

## Manifest (index.json)

Generated by `generate_indexes.js`. Contains one entry per extension with:
- `id`: `hayase.extension.nyaanew`
- `manifestVersion`: 2
- `code`: raw GitHub URL to the .js file
- `update`: raw GitHub URL to hayase/index.json
- `url`: base64-encoded origin URL (e.g., `https://nyaa.si` → `aHR0cHM6Ly9ueWFhLnNp`)
